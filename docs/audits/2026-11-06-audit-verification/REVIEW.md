## Dependency finding

DEVOPS-NEW-05 was checked with the actual lockfile and npm registry after explicit user authorization. The scan initially reported 12 advisory entries: one high, nine moderate and two low. Zod moved from 4.6.5 to 4.6.7 through a compatible override. The follow-up scan reports zero high/critical, nine moderate and two low entries, all in development tooling chains.

The remaining entries are not 11 independent runtime exploits: they include parent packages inheriting the same underlying glob/minimatch/deepmerge advisories. There is no patched deepmerge release in the [current advisory](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). npm's suggested forced changes would downgrade major tooling; those were not applied. No reachable application exploit was established for these remaining build-tool cases. The [Zod advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) identifies the patched range used here. The final registry result is preserved in `dependency-scan.json`.

## Upgrade and configuration notes

- Compose local AI users must set `AI_PRIVATE_BASE_URL` to the exact trusted base URL, matching provider settings. Native hosts use the `Ai:AllowedPrivateBaseUrls` array. AI redirects are disabled. See [settings](../../../SETTINGS.md).
- Native proxy deployments trust loopback by default. Configure `ReverseProxy:KnownNetworks` for other proxies. Compose passes `TRUSTED_PROXY_NETWORK`, defaulting to Docker's common `172.16.0.0/12` range; narrow it to the actual Compose subnet on shared hosts. The [ASP.NET Core guidance](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer?view=aspnetcore-10.0) explains the trust boundary.
- Backup API callers must use POST and the existing CSRF header. Both route aliases remain available. Frontend and generated types are updated.
- Missing/null translation updates preserve existing text; explicit blank updates clear it. Older queued status-only payloads remain compatible.
- Reader natural-key saves send optional `replaceExisting: true` to apply exact status/translation edits before server-ID recovery. Callers omitting it retain promotion-only create semantics. No invented negative ID is sent to a server PUT.
- New credentials require 12 characters; five failed logins lock the account for 15 minutes. Existing password hashes and session duration are unchanged. Placeholder JWT keys now prevent non-test startup.
- A future explicit language reset archives its scoped goals and rebases unfinished global delta goals in the same transaction. Existing goal data is not changed simply by upgrading.
- There is no database schema migration in this change. Changed historical text links are repaired when those texts are edited; no unsolicited bulk rewrite of existing texts was run.
- A subsequent feature implements password-free local setup through explicit `LINGUAREAD_LOCAL_MODE=true` (default false), with native, Docker web and Vite listeners local-only by default. It retains the existing owner and authorization/media policies, requires no JWT/password/setup token, and preserves existing credentials. Local hosts/origins and no-cookie CSRF requests are checked; the production Compose overlay forces both local flags off. See [settings](../../../SETTINGS.md).

## Independent review and corrections

The requested `remediation_reviewer` subagent reproduced four gaps in the initial remediation and provided failing regressions. These were corrected before its final follow-up:

| Finding | Correction and verification |
| --- | --- |
| R1 — stale ordinary-text linking | Current stored source and the owner transaction boundary now apply to ordinary texts as well as profiled texts. Named PostgreSQL word-key collisions restart the entire owner transaction rather than retrying within an unchanged Serializable snapshot. Tests cover stale input, distinct retry transactions, rollback after failures, exclusion of unrelated constraints and the retry limit. |
| R2 — stranded audiobook restoration | Manual transport actions cancel pending restore intent. The original reproduction now saves the manually selected track at 42 seconds after pause/unmount. Shared-source restoration still passes. |
| R3 — provisional word IDs and create-only edits | Exact reader save semantics, ordered coalescing and real-ID recovery preserve subsequent demotion, translation clearing and ID-based actions. Further review found omitted translations being replayed as empty and a disposal check occurring before an await; both were corrected with permanent regressions. |
| R4 — background audio expiry | Background requests participate in the shared sign-in flow. Unauthorized writes are retained, an empty queue can open login, and a real API/UI regression verifies retained reader state plus successful replay after authentication. |

The reviewer independently ran **64 frontend tests across 10 files and 11 backend tests across two classes**, all passing, and found no remaining actionable R1–R4 issues. Its backend run used the compiled assembly with `--no-build`; the full author run below rebuilt and tested the final source. See [REVIEWER.md](REVIEWER.md) for independent evidence and limitations.

The existing SQLite word-race test's interceptor previously awaited a competing insert inside the linker's newly required write transaction. That schedule cannot complete under SQLite's write lock. Its replacement independently schedules the actual linker and reader operations, releases the linker before awaiting the reader, and checks the final single word, reader status/translation, links and counts. Synthetic named-23505 tests separately verify transaction restart/rollback; neither establishes live PostgreSQL MVCC behavior.
